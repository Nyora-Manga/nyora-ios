# Nyora iOS 2.7.3 Release — Design

**Date:** 2026-08-05
**Repos:** `nyora-ios`, `nyora-ios-engine`, `nyora-data-driven` (read-only input), `nyora-android` (reference)

## Goal

Bring Nyora iOS to parity with Android 2.7.3: land the in-flight local changes, port the
recent Android app-level work, refresh the parser engine from current `nyora-data-driven`
state, sweep for bugs, bump 2.1.8 (11) → **2.7.3 (12)**, and ship an IPA through the
existing `release.yml` GitHub workflow (unsigned IPA + AltStore source update).

## Approach (decided)

**Approach A — local engine rebuild, vendored binary.** Build the xcframework locally from
current sources, vendor it into `nyora-ios` (Git LFS, as per `b3e1b117`), verify in-app,
then tag. `release.yml` stays a packager of committed state; no CI rework. (Approach B —
building the engine inside CI — was rejected as new CI surface this release doesn't need.)

## Workstream 1 — Land the in-flight changes (31 files)

Currently uncommitted in `nyora-ios`, grouped into logical commits after review:

1. **Colorizer removal** — deleted `iOS/Colorization/*` (`ColorizationController`,
   `MangaColorizer`, `ColorizationSettingsView`) plus edits in Settings, reader views,
   `Info.plist`, `Localizable.strings`, `AppDelegate`. Mirrors Android `22e4bc0`.
   *Review gate:* grep for dangling references (`Coloriz*`, settings keys, notification
   names, pbxproj file refs) — the build must be clean with zero orphans.
2. **Mihon backup import** — new `Shared/Data/Backup/Mihon/` +
   `AidokuTests/MihonBackupTests.swift` + `BackupsView` wiring.
   *Review gate:* tests pass; importing a real Mihon `.tachibk` round-trips library,
   categories, and history; malformed input fails gracefully.
3. **Translation polish** — new `iOS/Translation/MTPolish.swift` + edits to
   `GoogleTranslate`, `MangaTranslator`, `TranslationModels`.
4. **Reader tweaks** — `ReaderPageView`, `ReaderViewController`, paged/webtoon page
   controllers.
5. **CI/housekeeping** — `nightly.yml`, `release.yml` (+16 lines), `.gitignore`, `README`,
   `Package.resolved`, pbxproj. Stray `Nyora.ipa` at repo root is deleted, not committed.
6. **Simulator-slice deletions** in the vendored xcframework are superseded by
   Workstream 3 (fresh engine drop) — folded into that commit instead.

## Workstream 2 — Port Android changes not yet on iOS

From `nyora-android` since the last iOS sync:

- **Catalogue language / content-type filtering** (`ddd96a4` + `22e4bc0` catalogue work):
  apply the same language and content-type gating when rendering the source catalogue.
- **Sync account-settings fix** (`8b9774a`): verify whether the iOS sync client shares the
  bug; port the fix if it does, otherwise document why it doesn't apply.
- Android-only items explicitly **not** ported: ML Kit bump (`106c32e`, Android 16 KB
  page-size concern), APK/AAB CI changes.

## Workstream 3 — Engine refresh from nyora-data-driven

Input state (`nyora-data-driven` @ `5c57e74`):

- Asura: domain switched to `asurascans.com` (`asuracomic.net` kept as `altDomain`).
- 8 custom parsers ported to data-driven engines (15 real-user sources), matched to
  native kotatsu parsers (`7006d6e`).
- MangaPlus ported then marked broken (protobuf-only API) — must surface as dead on iOS,
  not as a silently empty source.
- `blocked-sources.json` / dead-source overlay updates.

Steps:

1. In `nyora-ios-engine`: regenerate `SourcePatches.kt` via nyora-data-driven's own
   generator (`generate-overlays.py --emit-kotlin com.nyora.ios.engine`) — never
   hand-edit.
2. `./gradlew compileKotlin` fast check, then
   `OUT_DIR=../nyora-ios/vendor/nyora-engine ./scripts/buildIosXcframework.sh`
   (device arm64 + simulator; Gluon GraalVM 22.1.0.1 / Java 17 per `NATIVE_IOS.md`).
3. Commit `nyora-ios-engine` (repo currently has **zero commits on master** — initial
   commit includes the untracked tree) and push.
4. Vendor the new xcframework into `nyora-ios` via Git LFS; verify LFS tracking so CI can
   fetch it.
5. In-app smoke: Asura loads under the new domain, at least 2 of the ported-engine
   sources browse + read, MangaPlus shows as unavailable rather than empty.

## Workstream 4 — Bug sweep, version, release

1. **Bug sweep:** full build with warnings reviewed; run unit tests; manual pass over
   library, browse, reader (paged + webtoon), backup import/export, translation, sync.
   Fix what's found; anything out of scope gets a tracked TODO, not a silent skip.
2. **Version:** `MARKETING_VERSION` 2.1.8 → `2.7.3`, `CURRENT_PROJECT_VERSION` 11 → `12`
   across all app targets in `project.pbxproj`.
3. **Release:** push `main`, tag `v2.7.3` → existing `release.yml` builds the unsigned
   IPA and `update_altstore_source.yml` refreshes the AltStore source. Verify the
   workflow run and the published source JSON.
4. Commit style per user rules: descriptive messages, no AI attribution of any kind.

## Testing summary

- `MihonBackupTests` + existing test suite green.
- Engine smoke tests (Workstream 3 step 5) on device or simulator.
- CI `lint.yml` + `release.yml` green on the tag; IPA installs via AltStore/sideload.

## Out of scope

- Building the engine inside CI (Approach B).
- New features beyond Android parity.
- App Store / signed distribution changes.
